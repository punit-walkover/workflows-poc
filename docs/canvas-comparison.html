Typebot-style vs React Flow

Two ways to build the workflow canvas, built side by side on the same graph and runner. This page compares how each one works, what it gives you, what it costs, and which to take into Ticket0.

Recommendation

Use React Flow for Ticket0. Keep the Typebot-style branch as a learning reference. With about the same amount of our own code, React Flow already includes the things the Typebot-style version was still missing: re-pointing arrows, box-select, a minimap and copy/paste. It is also MIT licensed, so nothing stands in the way of commercial use.

Typebot-style (from scratch)

@use-gesture + svg-round-corners + our own code

  • Best for learning: every piece is visible and ours
  • Full control over the look and behaviour
  • Tested end to end, including a live run
  • Every new canvas feature has to be built by hand
  • Arrow paths are adapted from Typebot (FSL), so they can't go into commercial Ticket0 as they are

React Flow (library)

@xyflow/react 12 (MIT) + our cards and arrows

  • Pan, zoom, drag, handles, selection, re-pointing and minimap all included
  • Same amount of our own code, with more features
  • MIT licensed, safe for Ticket0
  • Some library rules to follow (measured sizes, handle updates)
  • Built, but a few interactions are still to be tested

What is shared

Only the canvas layer differs. Everything under it is the same code on both branches, so either canvas can be swapped in without touching the server.

  • Saved graph: WorkflowGraph with groups, items and arrows, stored in workflow.graph and workflow_version.graph.
  • Runner: the Flow interface, graphFlow, loop backs with a trail, repeat limits and "ask again".
  • Validation: validateGraph, which checks reachability, one arrow per output, a limit on every loop, and at most 50 steps.
  • Editing helpers: web/src/lib/graph.ts, made of pure functions such as connect, removeItem and tidy. The React Flow branch adds moveItemTo, reconnect, removeMany and copyGroups/pasteGroups, and the other branch can use them too.
  • Page: undo/redo, Save, Publish, the step counter and the run panel's GraphRun.

How each one works

Typebot-style: we own the whole canvas

One div is moved with transform: translate() scale(). @use-gesture turns pointer moves into pan and drag. Each dot registers its element, and after every change the canvas measures every dot and draws arrows from those positions into an SVG layer. Connecting, palette drag and the arrow panel are all hand-written pointer handling.

React Flow: the library owns the canvas, we supply cards and arrows

Each group becomes a custom node (type: 'card'), and each arrow becomes a custom edge (type: 'wf'). Each case and each "then" is a <Handle type="source">. Each step, and the card's top, is a <Handle type="target">. React Flow measures handles itself and calls us back with changes: moves, connections, deletions and selection. We apply each one to the graph.

React Flow needs per-node state that the graph doesn't have: measured size, selection and dragging. The React Flow branch keeps that in a small ui map next to the graph and merges the two when it builds the node list. Positions still live only in the graph, so undo, save and tidy work the same on both branches.

What we learned building the React Flow version

  • Controlled nodes must keep measured. If the node list is rebuilt from the graph without each node's measured size, React Flow treats the nodes as unmeasured. Fix: keep size, selection and dragging in a ui map and merge them in.
  • The fitView prop didn't fit when nodes are rebuilt from the graph, and stayed at 100%. Fix: call fitView once useNodesInitialized() is true.
  • Reordering steps doesn't resize the card, so handle positions went stale. Fix: call useUpdateNodeInternals(id) whenever the card's items or cases change.
  • 'group' is a built-in node type with its own styling. Our type is named 'card'.
  • Dropping an arrow on a card body isn't a connection in React Flow, which only connects handle to handle. onConnectEnd checks what's under the pointer (data-drop) and connects there.
  • Arrow labels draw under the cards. React Flow's label layer sits below the nodes, and the default label spot for a backward arrow can fall on a card. The "↺ max 2" label in the test graph was hidden this way. Fix still to do: place backward-arrow labels on the arrow's vertical segment, beside the source card.
  • Undo for drags: an undo point is saved in onNodeDragStart, and every move during the drag is transient, so one drag is one undo.
